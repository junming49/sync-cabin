    作品说明
    1 · 需求分析与用户画像（3 类用户 · 痛点 · 功能响应）

    需求来源说明：本轮需求来自公开规范（GB 50763 等）与公开资料的桌面研究，未开展真实用户访谈与问卷，以下画像为典型场景归纳，供评审对照与后续访谈校验使用。

    • 画像 A · 轮椅使用者（自主出行的学生 / 来访者）
      核心痛点：① 常见导航只给"最短"路线，往往含台阶，走到跟前才发现过不去；② 不知道哪部电梯可用、坡道要绕多远；③ 门宽与窄通道信息缺失，容易卡在半路。
      功能响应：轮椅模式把"无台阶"设为硬约束（楼梯代价为无穷，直接判定不可达）；三种策略并排给出步数 / 台阶数 / 转弯数 / 是否经坡道，把绕行代价交由使用者自己权衡；窄通道单独标注并计入代价；路线结果给出风险提示（经过 N 处窄通道）。
    • 画像 B · 低视力者
      核心痛点：① 界面字号与对比度不足，看不清网格与按钮；② 台阶与高差难以目视发现；③ 视线不敢离开画面去读长段说明。
      功能响应：低视力模式自动切换到 1.3 倍字号 + 高对比 + 语音播报优先（浏览器不支持时降级为文字提示）；台阶数与步数并列显示为一等指标；全部状态变更经 aria-live 区域播报，可只听不看完成导航。
    • 画像 C · 听障者
      核心痛点：① 语音播报类提示完全接收不到；② 视觉提示一闪而过，容易漏掉关键信息；③ 嘈杂环境（如报告厅散场）下无法依赖听觉广播。
      功能响应：听障模式关闭语音，改用文字提示条 + 视觉高亮闪烁承载全部播报内容；完整路线步骤列表常驻可回看，不依赖时效性提示，随时能补看漏掉的信息。

    共性需求 → 共同响应：三类偏好共享同一套状态机与同一份路线数据，任一交互通道（键盘 / 屏幕方向键 / 文字指令 / 语音）都能独立完成"选目的地 → 比路线 → 导航 → 导出报告"全流程，避免"少了某个通道就用不了"。

    需求 → 功能对照（可核验）：无台阶硬约束 → 轮椅模式楼梯代价无穷；横向比较 → 三策略并排卡片与量化指标；通道替代 → 三种偏好的差异化提示通道；信息可留存 → 行程报告 JSON / 文本导出；任何学校可用 → 自定义地图编辑与导入导出。

    2 · 作品简介与目标用户

    作品定位：一个离线可运行的室内无障碍导航原型，覆盖虚构实验楼的一层与二层，共 6 个目的地、3 类垂直交通（楼梯 / 坡道 / 电梯）。

    目标用户：轮椅使用者、低视力使用者、听障使用者，以及需要在陌生公共建筑中快速理解"哪条路更适合我"的普通访客与陪同人员。

    要解决的问题：常见导航只给一条"最短"路线，使用者无法知道这条路是否有台阶、是否经过窄通道、是否必须等电梯。本作品把这些信息量化后并排呈现，允许使用者自己决定。

    3 · 创新点（3 条，及与常见校园地图 / 导航应用的差异）

    创新点一：偏好驱动的加权寻路 + 三策略并排对比。同一目的地同时计算"最短路径 / 无障碍优先 / 少台阶"，并逐项量化步数、台阶数、转弯数、是否经过坡道，可一键采用任一条。
    差异：常见校园地图只输出单一最短路径，台阶与绕行信息缺失或仅以文字备注出现，无法横向比较。

    创新点二：多模态"同义"交互。键盘方向键、屏幕方向键盘、文字指令（带地点别名容错与失败兜底提示）、语音播报四种通道操作同一套状态机，任一通道都能独立完成"选目的地 → 比路线 → 导航 → 导出"全流程。
    差异：常见导航以触屏点选为唯一主通道，其余通道多为附加功能，缺一不可用的情况普遍存在。

    创新点三：通道替代而非通道叠加。听障模式关闭语音并以"视觉高亮闪烁 + 文字提示条"替代；低视力模式自动切换到最大字号、高对比与语音优先；轮椅模式把"无台阶"升级为硬约束。
    差异：常见做法是把无障碍当作附加设置项，切换后不改变路线结果，也不改变提示通道的主次关系。

    4 · 技术路线
    • 网格建模：2 层 × 7 列 × 5 行，共 70 个节点；节点邻接为同层四向移动 + 垂直连接（楼梯 / 坡道 / 电梯）。不可通行格、窄通道格作为节点属性参与代价计算。
    • 寻路算法：所有边权均为正数，使用 Dijkstra（小规模数组优先队列）求最短路；一次规划同时以三种权重表各跑一遍，得到三条候选路线。
    • 偏好权重设计：总代价 = 基础移动 1 + 窄通道（模式权重 + 策略权重）+ 垂直连接代价。坡道含绕行代价、电梯含候梯代价、楼梯按模式与策略叠加台阶惩罚；轮椅模式下楼梯代价为无穷（不可通行）。
    • 无外部依赖：纯 HTML + CSS + 原生 JavaScript，无构建、无框架、无网络请求；语音使用 Web Speech API 并做能力检测，不支持时降级为文字提示。
    • 无障碍工程：尊重 prefers-reduced-motion、:focus-visible 焦点环、aria-live 播报区、抽屉 Esc / 遮罩关闭与焦点返回、移动端单列适配。
    5 · 操作与运行说明
    • 运行：直接用浏览器打开本 HTML 文件即可，无需安装、构建或联网。
    • 鼠标 / 触屏：选偏好模式 → 选目的地 → 在策略卡片点"采用这条" → 点"沿路线前进一步"逐步导航，也可用屏幕方向键盘自由移动。
    • 键盘：Tab / Shift+Tab 遍历控件；方向键在当前楼层移动；◎ 或"播报当前位置"查询所在位置；文字指令输入框回车即执行；Esc 关闭作品说明抽屉。
    • 文字指令示例：去图书馆、去厕所、去南门、去报告厅、去电梯、去休息区（支持别名，如"卫生间""礼堂""升降梯"）。
    • 录入自己的校园：在页面下方"录入自己的校园"面板选工具后点格子即可编辑网格与目的地，保存到本机并可导出 / 导入地图 JSON；地图数据只存本机，不上传。
    • 预计时间与风险提示：路线卡片与导航区给出"步数 × 0.8 m、× 1.2 秒"的示例估算结果与风险提示（窄通道、台阶、电梯候梯），该估算未做实测校准。
    • 导出：行程报告含偏好模式、起终点、采用路线、逐步指令、台阶 / 坡道统计、预计时间、风险提示、无障碍自检结果与地图来源，支持 JSON 与纯文本两种格式，保存在本地。

    7 · 数据与安全说明
    • 不采集个人信息：无账号、无注册登录、不要求姓名 / 学号 / 手机号 / 位置授权，不读取设备信息。
    • 不上传：页面无任何网络请求——没有 fetch / XMLHttpRequest / 外链脚本 / 外链字体 / 图片资源，全部计算在浏览器本地完成；导出的报告与地图文件由使用者手动保存到本机。
    • 本机存储内容：自定义地图（localStorage 键 tongpin.map.v1）与界面偏好（无障碍模式、语音、高对比、大字、减少动效，键 tongpin.prefs.v1），仅本设备可见，不同设备之间不同步。
    • 可一键清除：点下方按钮即删除上述两个键并恢复内置示例地图，无需卸载或清理浏览器设置。存储不可用时（隐私模式 / 空间不足），页面降级为"本次会话内有效、关闭即失效"并给出文字提示，不静默失败。
    • 已知限制与风险：localStorage 为明文存储，公用电脑使用后建议点清除；本作品未做加密与访问控制，不应用于保存真实个人信息；自定义地图若录入真实建筑，其尺寸与设施信息由录入者负责核实。
